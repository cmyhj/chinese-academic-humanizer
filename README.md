# Chinese Academic Humanizer：面向中文工科学术文本的上下文保真编辑方法

## 摘要

中文学术文本的编辑不仅涉及词语和句式调整，还涉及论证组织、研究对象、条件限定及证据层级的准确表达。针对局部措辞修改难以处理跨段逻辑与科学含义偏移的问题，本文介绍 Chinese Academic Humanizer，一种以 AI Agent Skill 形式组织的上下文保真编辑方法。该方法先检查章节论证与段落职责，再开展句级改写，并复核术语、物理量、因果关系、时序及结论适用范围。默认文风依据机械、机器人和航空工程领域的中文论文归纳，允许按作者样本及投稿要求调整。本文通过四组经授权的机器人论文旧稿片段说明具体编辑方式，同时给出技能部署、结构检查与文件交付的适用条件。所列案例用于解释编辑规则，不构成定量性能评估，也不支持关于 AIGC 检测率的结论。

**关键词：**中文学术写作；上下文编辑；科学保真；工程论文；AI Agent Skill

## 1 引言

学术表达需要同时说明研究对象、所采用的方法及结论成立的条件。句子在语法上通顺，并不意味着其研究范围、因果层次和证据强度均已准确表达。例如，抽象的性能要求可能掩盖具体作用过程，段末评价可能重复前文已经说明的约束，而对局部试验现象的概括也可能超出原有证据范围。因此，文本编辑需要结合相邻段落和章节任务判断，不能仅以近义词替换或句长调整为依据。

本项目参考 academic-humanizer 的主张与证据匹配原则，以及 humanizer-zh-academic 的中文表达模式分类，将编辑过程组织为论证检查、段落分析、句级改写和语义复核。默认叙述方式依据中文机械、机器人和航空工程论文[1–3]归纳，适用于中文期刊论文、学位论文、毕业设计报告和科技报告。

本项目的目标是改善表达的准确性与连贯性，不判断文本作者是否使用 AI，也不以规避 AIGC 检测为用途。编辑过程不得虚构数据、研究经历或参考文献，AI 辅助使用仍应遵守学校、期刊及研究机构的披露要求。

## 2 编辑方法

### 2.1 上下文分析与分层改写

全文深度编辑从章节任务开始，依次检查各节所回答的问题、段落之间的承接关系及句子承担的信息功能。在此基础上调整表达，避免以局部流畅性替代整体论证的完整性。主要处理层次如下。

| 层次 | 检查对象 | 处理内容 |
| --- | --- | --- |
| 章节论证 | 研究问题、方法与结果的对应关系 | 判断章节是否围绕明确问题展开，结论是否回应既定任务 |
| 段落组织 | 段落职责、相邻段落承接与信息重复 | 明确各段对象，整合重复说明，梳理已有信息之间的逻辑联系 |
| 句级表达 | 主语、术语、条件、并列及因果层次 | 在不新增事实的前提下调整措辞、句序和句内结构 |
| 语义复核 | 数据、物理量、时序、比较对象与证据类型 | 核对改写是否保留原文的科学含义及适用范围 |
| 跨章一致性 | 术语、研究范围及中英文摘要命题 | 复核各章与摘要对同一对象和结果的表述是否一致 |

上述层次不要求机械地重复改写全文。原句经上下文检查后不存在问题时，可以保留。用户仅授权局部润色或纠错时，处理范围以该授权为准，不因采用全文分析方法而扩大修改边界。

### 2.2 科学含义保护

科学保真不仅指数字一致，还包括研究对象、物理量、条件、比较关系、因果、时序及证据层级的一致。设计目标、理论预测、数值仿真、实物试验与潜在应用应分别表述，不得在编辑中相互替代。

对于机理解释，改写后的因果强度应与原有证据相符；对于试验结论，应保留相应工况和验证范围。原稿存在证据缺口或物理量混淆时，应先核查材料，不能通过增加限定词或调整语气将其视为已解决的问题。语言编辑也不能替代对模型、原始数据和科学结论的专业审查。

### 2.3 默认文风与校准依据

默认文风强调以任务和约束引出方案，以组成、连接和动作说明结构，以条件、过程和结果组织分析。建模段落先交代对象、假设和变量；结果段落明确证据类型，并将结论限定于对应指标和工况。具体准则及来源页码见 [default-engineering-style.md](references/default-engineering-style.md)。

正常的连接词、固定学术表达、中长句和同层并列不被视为必须消除的形式。是否修改取决于其信息功能，而非词频、句长或预设修改数量。默认样本用于归纳叙述方法，不用于移植研究事实；作者当轮提供的文风样本及学校、期刊规范优先于默认规则。全文处理与语义验收流程见 [deep-editing-workflow.md](references/deep-editing-workflow.md)。

## 3 案例分析

以下片段来自提供者授权展示的机器人论文旧稿。修改文本结合原稿上下文审定，用于说明编辑规则及其适用条件，不属于自动运行基准，也不代表对全文科学结论的独立验证。仓库仅公开必要片段，不公开原始文稿、个人信息或原始实验数据。

### 3.1 具体过程与抽象要求的转换

**原文（节选）**

> 黏附能力须同时覆盖新接触的建立与旧接触的解除，两者在时间上重叠，不能靠先后次序回避。

**修改文本**

> 过渡过程中，目标面需在原表面接触解除前形成有效附着，以维持整机的连续支撑。

原文以“覆盖”和“回避”描述接触过程，但没有直接说明新旧接触之间的支撑关系。修改文本依据同段已有的失效描述，将其转化为目标面附着与原表面接触解除的时序要求，并明确该要求与连续支撑的关系。该处理依赖原文上下文，不适用于缺乏相应机理依据的段落。

### 3.2 研究范围的正面界定

适用上下文：前文已明确列出五类正交壁面外过渡。

**原文**

> 该定义只强调过渡类型的完整覆盖，并不表示机器人已验证任意夹角或任意姿态下的过渡。

**修改文本**

> 本文研究范围为正交壁面间的上述五类外过渡。

修改文本直接界定研究所覆盖的对象和工况，减少对未作出何种主张的解释，同时保留正交壁面与五类外过渡的范围约束。这种处理并非删除必要限定，更不能据此将结论扩大到任意夹角或任意姿态。

### 3.3 重复性段末评价的处理

**原文（节选）**

> 与轮足相比，履带可在较长区间维持接触，但循环运动需要持续组织接触区前缘的附着和后缘的脱附；当表面方向发生突变时，还需要履带及支撑机构具有相应的变形或姿态调节能力。因此，连续接触的优势并不直接等同于跨凸棱能力。

**修改文本**

> 与轮足相比，履带可在较长区间维持接触，但循环运动需要持续组织接触区前缘的附着和后缘的脱附；当表面方向发生突变时，还需要履带及支撑机构具有相应的变形或姿态调节能力。

原文前句已说明接触连续性之外的附着、脱附及姿态调节要求，末句未增加新的条件或机理。因此，修改保留具体分析，删除重复评价，其余表达不变。删除依据是信息重复，而不是将“并不等同于”规定为禁用句式。

### 3.4 试验命名与因果层次

**原文**

> 树干试验表明，高度不规则的表面使两侧轮足先后接触、机体倾斜，进而引起预载失衡。

**修改文本**

> 树干表面爬行试验表明，树皮表面的起伏会使两侧轮足接触不同步，进而引起机体倾斜和预载分配不均。

“树干试验”仅说明试验对象，未说明执行任务。修改文本补明“表面爬行”，并区分表面起伏、接触状态与机体响应，按原稿所采用的机理解释组织因果层次。

该改法以证据支持相应因果关系为前提。“会使”并非必须添加的表达，也不能据此将一次观察概括为一般规律。如果证据仅支持现象描述，应采用以下表述：

> 在树干表面爬行试验中，观察到两侧轮足接触不同步，并伴随机体倾斜和预载分配不均。

四组案例分别涉及过程具体化、范围界定、重复信息处理及观察与机理的区分，其共同依据是对象、逻辑和证据关系，而非机械删词。本文未提供大规模语料评估或对照试验，不能据此推断方法在不同学科、模型和文本类型上的普遍效果。

## 4 实现与使用

### 4.1 任务输入

任务输入应说明文本或文件、授权范围、风格依据及需保留的内容。以下分别给出局部润色、全文深度编辑与 Word 修订的请求示例。

```text
使用 chinese-academic-humanizer，润色以下中文论文段落。
保留数据、术语、引文和适用条件，输出改写结果及主要修改理由。
```

```text
使用 chinese-academic-humanizer，参考我提供的论文文风，
对这份文稿做全文深度优化。先检查论证链和段落职责，
再逐句处理；不要只换词，不新增事实。
```

```text
使用 chinese-academic-humanizer，润色这份 Word 的第二章。
只改授权正文，保留既有批注和修订，使用原生修订，原文件不覆盖。
```

`/chinese-academic-humanizer` 是否可作为斜杠命令使用，取决于所用客户端及其技能加载方式；自然语言指定技能名也可使用。

### 4.2 Hermes Agent 部署

Hermes Agent 可通过直接指向 `SKILL.md` 的 URL 安装：

```bash
hermes skills install https://raw.githubusercontent.com/cmyhj/chinese-academic-humanizer/main/SKILL.md
```

安装后需确认主文件和两份 `references/` 文件均已取得。如果所用版本的 URL 安装器仅下载主文件，应采用完整仓库部署方式。

### 4.3 完整仓库部署

```bash
git clone https://github.com/cmyhj/chinese-academic-humanizer.git
```

完整目录可放入客户端实际配置的技能根目录，也可将仓库路径交给 Agent 读取。技能根目录取决于客户端、操作系统和 profile 配置。部署过程应保留安装器要求的审查与确认，不宜绕过扫描或强制信任。

### 4.4 文件组织

本项目以提示规则和参考准则构成技能包，主入口为 [SKILL.md](SKILL.md)。`references/` 是技能的组成部分，部署时应保留完整目录，不能仅复制主文件。

```text
SKILL.md
references/
  default-engineering-style.md  # 默认文风、章节叙述、固定表达及来源锚点
  deep-editing-workflow.md      # 全文深度编辑与语义验收
scripts/
  validate_skill.py             # 包结构、相对引用和发布内容检查
tests/
  test_validate_skill.py
```

## 5 质量检查与适用限制

### 5.1 技能包结构检查

本地检查使用 Python 3.10 及以上版本，仅依赖标准库：

```bash
python scripts/validate_skill.py
python -m unittest discover -s tests -v
```

检查对象包括主技能元数据、内部引用、UTF-8 编码及发布内容中的明显本机路径和敏感标记。此类检查用于发现技能包的结构问题，不属于完整安全审计，也不能证明文稿的语言质量或科学结论已经通过审查。

### 5.2 运行依赖与适用边界

纯文本编辑不依赖 Python 或 Microsoft Word，但需要能够读取并遵循技能规则的模型与客户端，实际效果受模型能力、上下文长度和输入材料完整性影响。

`docx`、`word-tracked-revisions` 和 `pdf` 是原运行环境中的协作技能名称，未随本仓库打包。其他客户端应自行提供等效的文档读写、PDF 抽取、修订及验收能力；缺少相应工具时，不能声称已经执行文件操作。Word 原生打开及接受、拒绝修订的验收通常需要安装 Microsoft Word 的 Windows 环境和可用自动化工具，仅设置 `TrackRevisions=True` 不足以证明所有改动均被正确记录。

正式 Word 修订除语言检查外，还需保护既有批注、修订及未授权对象，并通过接受修订、拒绝修订和文件实际打开等检查核对交付结果。绿色高亮默认视为作者锁定，是本技能的保护约定，并非 Word 或学校的通用标准；用户可明确指定其他标记约定。

本项目提供编辑准则，不包含通用 Word 修订执行器、AIGC 检测器或自动科学核验系统。默认文风样本也不代表全部学科的统一规范。对证据不足、方法描述缺失及专业判断存在争议的内容，仍需作者结合原始材料作出判断。

## 6 结论

Chinese Academic Humanizer 将中文工科学术文本的编辑组织为上下文分析、分层改写与科学含义复核，强调在授权范围内说明对象、过程、条件和证据关系。四组案例展示了具体过程表达、研究范围界定、重复评价处理及试验叙述调整的实施方式。该方法的作用是为 AI 辅助编辑提供可检查的规则，不能替代作者对研究事实、专业结论和最终提交文本的责任。其跨学科适用性与编辑效果仍需结合具体文本和独立评估判断。
